# VDB Manager

Kiwoom 코드가 vector DB 를 쓰는 통로다. 임베딩 추론과 Qdrant 접근은 게이트웨이
(VDB Handler Service)가 맡고, 이 패키지는 그 앞에 서는 HTTP 클라이언트다. 여기 적는
것은 이 영역에서 낱말이 무엇을 가리키는가이지 어떻게 구현했는가가 아니다.

## Language

### 무엇을 고르는가

두 낱말이 모두 "고른다" 로 읽혀 자주 뒤바뀐다. 축이 다르다.

**포인트 고르기**:
어떤 포인트를 대상으로 삼을지 정하는 일. 인자는 `payload_filter` 이고 조건에 맞는
포인트만 남긴다.
_Avoid_: 필터링, 검색(검색은 벡터 유사도로 찾는 별개의 일이다)

**항목 고르기**:
고른 포인트에서 payload 의 어떤 항목을 받아 올지 정하는 일. 인자는 `with_payload`
이고 대상 포인트의 수를 바꾸지 않는다.
_Avoid_: payload 필터, 필드 필터

### 데이터의 단위

**포인트**:
Qdrant 에 저장되는 한 건. 벡터와 payload 와 id 를 갖는다.
_Avoid_: 문서, 레코드, 청크 — 문서 하나가 포인트 여럿이 되는 소비자가 있어 둘을
같은 말로 쓰면 "적재 완료" 판정이 어긋난다.

**payload**:
포인트에 매달린 key-value 뭉치. **포인트마다 스키마가 없다** — 같은 컬렉션 안의
포인트들이 공통 키를 하나도 갖지 않아도 정상이다.
_Avoid_: 메타데이터(적재 인자 이름은 `metadatas` 이지만 저장된 뒤에는 payload 다)

### 훑는 방식

**순회**:
컬렉션의 포인트를 처음부터 끝까지 한 번씩 보는 일. `iter_points` 가 담당한다.
_Avoid_: 스크롤, 페이지네이션 — 그것은 순회를 이루는 수단이지 목적이 아니다.

**이어받기 키**:
다음 페이지가 어디서 시작하는지 가리키는 값. 응답의 `next_offset` 이며 끝은
`None` 으로만 판정한다 — `0` 은 실재하는 포인트 id 다.
_Avoid_: 커서, 오프셋

### 층

**게이트웨이**:
이 패키지가 HTTP 로 부르는 서버(`KiwoomAM/Kiwoom-Handler` 의 vdb-handler). 임베딩과
Qdrant 접근이 전부 그쪽 소관이다.
_Avoid_: 서버, 핸들러, 서비스 — 형제 패키지마다 가리키는 대상이 달라진다.

**바로가기**:
`VDBManager` 가 하위 클라이언트의 메서드를 같은 이름·같은 인자로 한 벌 더 갖는 것.
`handler.count_points(...)` 는 `handler.collection.count_points(...)` 와 같다.
_Avoid_: 프록시, 위임 메서드, 별칭
