# Phase 1 — `file_meta` 응답 노출 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/v1/request` 응답의 `meta` dict 에 `file_meta` 필드를 추가하여 file-manager 가 부여한 `file_path` 를 호출자가 받게 한다.

**Architecture:** meta 가 만들어지는 3 곳 (`_build_live_meta`, `prepare`'s `cached_meta`, `fetch_by_cache_key`) 에 각각 조건부로 `file_meta` 키를 추가. SDK `RequestMeta` 모델에도 `file_meta: list[dict] | None = None` 필드 추가. 동작은 MongoDB doc 의 `file_meta` 키와 1:1 거울 매칭.

**Tech Stack:** Python 3.x / FastAPI / Pydantic v2 / pytest / MongoDB / Redis

**Spec:** [docs/18.file-meta-response-exposure.md](./18.file-meta-response-exposure.md) Phase 1 블록 (§1~§9)

def _build_live_meta(prep: _Prepared) -> dict[str, Any]:
    """live 호출의 meta dict를 구성한다."""
    meta: dict[str, Any] = {
        "source": "live",
        "cache_hit": False,
        "cache_key": prep.dc.cache_key if prep.dc else None,
        "metadata": prep.meta,
        "collection": prep.dc.collection if prep.dc else None,
    }
    file_metas = _dump_files_meta(prep.files)
    if file_metas is not None:
        meta["file_meta"] = file_metas
    if prep.debug and prep.route_reason:
        meta["route_reason"] = prep.route_reason
    return meta
```

### `meta.file_meta` 가 응답에 없는데?

세 가지 원인:

1. **호출에 `files` 인자가 없음** — `meta.file_meta` 키는 `files=[..]` 일 때만 노출됨 (files=None / 빈 list 면 키 자체 부재). 의도된 동작.

2. **옛날 (Phase 1 적용 전) 캐시 doc 의 cache hit** — Phase 1 적용 전에 저장된 doc 에는 `file_meta` 가 없어 cache hit 응답에도 키 없음. 새 호출 또는 캐시 갱신 후 노출됨.

3. **옛 SDK 사용** — `RequestMeta` 모델에 `file_meta` 필드가 정의된 SDK 버전인지 확인 (`from llm_request.models import RequestMeta` 후 `RequestMeta.model_fields`). 옛 SDK 는 `extra="ignore"` 로 키 자체를 폐기.

→ 안전 접근: `meta.get("file_meta")` (dict) 또는 `getattr(meta, "file_meta", None)` (RequestMeta) 사용.

### SDK ↔ Service 버전 매트릭스

| | 옛 SDK (`RequestMeta` 에 필드 없음) | 새 SDK (필드 있음) |
|---|---|---|
| **옛 Service** (`file_meta` 안 보냄) | ✅ 정상 | ✅ 정상 (default `None`) |
| **새 Service** (`file_meta` 보냄) | ✅ 정상 (Pydantic v2 `extra="ignore"` 로 모르는 키 폐기) | ✅ 의도된 동작 |

→ **자연 호환** — 어떤 조합이어도 깨지지 않음.
````
