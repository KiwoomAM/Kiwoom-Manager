# 20. Context Cache Expire — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** agent 가 task 종료 시점에 Context Cache 의 TTL 을 단축할 수 있는 SDK / HTTP API 를 추가한다.

**Architecture:** 응답에 `context_cache_id` (내부 hash_key, opaque token) 노출 → agent 가 단축 시점에 `expire_context_cache_async(ids)` 호출 → Service 는 Redis 정방향 조회 → Gemini `caches.update(ttl=grace)` + Redis EXPIRE. Reverse index 신설 없이 1 GET 으로 처리.

**Tech Stack:** Python 3.11+, FastAPI (Service), httpx (SDK), Pydantic v2, Redis (`BaseJsonStore`), `llm_handler.aio.update_cache`, pytest.

**Spec:** [20.context-cache-expire.md](20.context-cache-expire.md)

**Notes:**
- 메모리상 git 명령은 사용자가 직접 실행 → plan 의 commit step 은 **사용자가 실행**, Claude 는 코드만 변경.

```python
"""Context Cache lifecycle — expire 처리.

resolver 의 생성 로직과 분리. 단축 처리 (Gemini update + Redis EXPIRE) 만 담당.
"""

from __future__ import annotations

import asyncio
import logging

from llm_handler import aio as llm_aio

from app.logic.file_processing import cache_store
from app.models.responses import ExpireContextCacheResponse, ExpireFailure

logger = logging.getLogger(__name__)


def _is_not_found_error(exc: Exception) -> bool:
    """Gemini 404 NotFound 패턴 식별."""
    msg = str(exc).lower()
    return "not found" in msg or "404" in msg


async def expire_caches(
    cache_ids: list[str],
    grace_seconds: int,
) -> ExpireContextCacheResponse:
    """다중 cache_id 동시 expire — partial failure 허용."""
    results = await asyncio.gather(
        *[_expire_one(cid, grace_seconds) for cid in cache_ids],
    )
    expired = [r["cache_id"] for r in results if r["status"] == "expired"]
    failed = [
        ExpireFailure(cache_id=r["cache_id"], error=r["error"])
        for r in results if r["status"] == "failed"
    ]
    return ExpireContextCacheResponse(expired=expired, failed=failed)


async def _expire_one(cache_id: str, grace_seconds: int) -> dict:
    # ① Redis 조회 (cache_id == hash_key)
    try:
        doc = cache_store.find_context_cache(cache_id)
    except Exception as e:
        logger.exception("Redis 조회 실패: cache_id=%s", cache_id[:16])
        return {"cache_id": cache_id, "status": "failed", "error": str(e)}

    if not doc:
        # idempotent — 이미 정리됨/만료됨
        return {"cache_id": cache_id, "status": "expired"}

    name = doc["cached_content_name"]

    # ② Gemini update
    try:
        await llm_aio.update_cache(name, grace_seconds)
    except Exception as e:
        if _is_not_found_error(e):
            return {"cache_id": cache_id, "status": "expired"}
        logger.exception("Gemini update_cache 실패: cache_id=%s", cache_id[:16])
        return {"cache_id": cache_id, "status": "failed", "error": str(e)}

    # ③ Redis TTL 단축 (실패해도 expired — Gemini 비용은 단축됨)
    try:
        cache_store.shrink_context_cache_ttl(cache_id, grace_seconds)
    except Exception:
        logger.exception(
            "Redis TTL 단축 실패 (Gemini는 단축됨): cache_id=%s", cache_id[:16],
        )

    return {"cache_id": cache_id, "status": "expired"}
```

> `llm_handler.aio.update_cache(name, ttl)` 시그니처 확인됨: `ttl: int` (초 단위 정수). doc 에 적힌 `ttl="60s"` 표기는 자연어 설명용 — 실제 호출은 `update_cache(name, 60)`.

`context_cache_ttl` 로 길게 잡아두고 task 가 끝났을 때 SDK 로 단축할 수 있다.
TTL 만큼 storage 비용이 분 단위 prorate 청구되므로, 길게 잡고 끝나면 줄이는
패턴이 비용 효율적이다.

\```python
from llm_manager import llm_request_async, expire_context_cache_async, StoredFile

cache_ids: set[str] = set()
for q in questions:
    response, meta = await llm_request_async(
        {"contents": q, "model": "gemini-2.5-flash"},
        stored_files=[StoredFile(**sf_dict)],
        timings={"context_cache_ttl": 3600},
    )
    if meta.context_cache_id:
        cache_ids.add(meta.context_cache_id)

# task 끝나면 cleanup
result = await expire_context_cache_async(list(cache_ids))
print(result.expired, result.failed)
\```

| 인자 | 기본값 | 설명 |
| --- | --- | --- |
| `cache_ids` | — | 응답 `meta.context_cache_id` 로 받은 식별자 리스트 |
| `grace_seconds` | `60` | in-flight 요청 보호. Gemini 측 새 TTL (1~3600) |

청구는 `caches.update` 기반이라 단축 시점까지로 prorate. delete 가 아니라 update 사용 이유는 [docs/20.context-cache-expire.md](docs/20.context-cache-expire.md) 참고.
```
