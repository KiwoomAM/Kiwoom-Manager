# llm-request: 서버 레이어 제거 → 순수 SDK manager 리팩토링 계획

> 상세 구현(모듈별 세부·로드맵·사용 예시·TODO)은 이후 섹션별로 채운다.
> 현재까지: 배경 / 개요 / 사전정보 / 패키지구조 / 공개 API 표면 / 의식사항.

## 1. 배경

### 현재 구조와 문제 제기

llm-request는 지금 **2겹**으로 돼 있다.

```
사용자 → sdk/(얇은 httpx 클라이언트) → service/(FastAPI 서버) → logic/ → handlers
```

`service/app/logic/`이 실제 manager 본체(mdb·redis·llm·file handler를 in-process로 조합)인데,
이걸 FastAPI 서버로 감싸고 다시 httpx SDK로 호출하는 우회 구조다.
여기서 "llm-request가 **서버화될 필요가 있는가**"라는 질문이 나왔다.

### handler / manager taxonomy

- **handler = 서버.** 외부 시스템 하나를 감싼다(Mongo·Redis·Gemini·파일). 서로 못 부름. 외부 사용자는 코드 모르고 URL만.
- **manager = SDK.** handler들을 "우리가 원하는 방식"으로 조합한 wrapper. 외부 사용자가 직접 import해서 씀.

이 정의에서 **llm-request는 handler가 아니다** — 자기 소유의 외부 리소스가 없고, 다른 handler들을 조합(orchestrate)할 뿐이다. 그건 정확히 **manager의 일**이고, manager는 SDK다. (caching agent라는 표현도 file-manager가 SDK인 것과 같은 의미의 SDK manager이지 서버가 아니다.)

### 서버화 근거 검토 — 전부 소멸

| 서버화 근거 | 결론 |
|---|---|
| 자격증명 중앙화 | ✗ cert는 전 agent 공통, handler URL은 하드코딩, Gemini key는 사용자 설정 → 중앙화할 게 없음 |
| Gemini 호출량/레이트리밋 제어 | ✗ llm-handler가 담당 |
| 로직 독립 배포(버전 스큐 방지) | ✗ 전 소비자를 한 번에 SDK로 전환(atomic cutover) → 버전 스큐 자체가 없음 |
| 무거운 의존성 격리 | ✗ 설치 1회뿐, 이후 무관 |
| 캐시 키 결정성(단일 소스) | ✗ keying canonicalize를 **동결 계약**으로 두면 SDK 분산 배포해도 안전. file-manager도 동일 트레이드오프를 이미 수용 (§6) |
| byte 경로 / manager↔handler 잡담 | ✗ **아래 토폴로지 참고** — 같은 LAN이라 무손실 |
| 상사 방침: 사용자는 SDK로만 접근 | → 서버로 두면 "감싸는 SDK를 또 만들어야" 함 = 2겹은 불필요한 군더더기 |

### 네트워크 토폴로지 (byte 경로 caveat이 무효인 이유)

- handler들과 agent PC가 **모두 같은 서브넷(`192.7.9.x`, 같은 LAN)** 에 있다.
- manager는 handler와 **수다스럽다**(cold 요청 1건당 done_check·dedup standby·find/save·fetch·upload 등 핸들러 왕복 10~15회).
- manager가 어디서 돌든 이 왕복은 **LAN(sub-ms)** 이라 cold라도 총 몇 ms → 무시 가능.
- warm(캐시 HIT)은 원래부터 양쪽 1 왕복으로 동일.
- 속도 계층: loopback(같은 머신·다른 포트, µs) > LAN(같은 서브넷, sub-ms) > WAN(인터넷, 10~50ms).
  서버화가 byte 경로에서 이득을 보는 경우는 **agent가 WAN 너머 + cold 대용량 파일이 잦을 때**뿐인데, 같은 LAN이므로 해당 없음.

### 결론

서버 레이어를 유지할 근거가 남지 않는다. **llm-request는 순수 SDK manager로 전환한다.**

## 2. 개요

### 목표 형태

```
[현재]  사용자 → sdk/(httpx) → service/(FastAPI) → logic/ → handlers   (2겹)
[목표]  사용자 → llm-request SDK(= 기존 logic/ 본체) → handlers        (1겹)
```

### 작업 윤곽

- **제거**: `service/app/main.py`, `service/app/routers/`, `sdk/`의 httpx 왕복 경로
- **승격**: `service/app/logic/`을 llm-request manager SDK의 본체(`_internal/`)로
- **유지**: public API 시그니처(`llm_request_async`, `llm_request`, `done_check`, `fetch_by_cache_key`, `delete_cache*` 등)는 그대로. 내부 배선만 "httpx로 서버 호출" → "logic 직접 호출"로 교체

→ 사용자 import(`from llm_request import llm_request_async`)는 **변경 없음**. 외부 영향 0, 내부 한 겹만 걷어내는 작업.

## 3. 사전 정보 — HTTP에 묶여 있어 바뀌는 지점

| 대상 | 처리 |
|---|---|
| `sdk/_client.py` (httpx 클라이언트) | **제거.** public 함수가 logic을 직접 호출 |
| `service/app/main.py` (FastAPI lifespan·에러핸들러·미들웨어) | **제거.** lifespan의 handler 초기화는 SDK 초기화로 이전 |
| `service/app/routers/request.py` (5 엔드포인트) | **제거.** 핸들러 함수 본문 로직은 이미 logic에 존재 |
| `service/app/models/requests.py·responses.py` (HTTP DTO) | **대부분 제거.** 입력 타입(StoredFile/FileInput 등)만 존치 (→ 추후 §) |
| `service/app/config.py` (port·host·handler URL) | port/host 제거, handler URL 하드코딩 상수화 |
| 예외 2계층 (sdk exceptions ↔ service core/errors) | HTTP relay 소멸 → logic 예외가 사용자에게 직접 (→ §5) |
| `logic/*` (keying·done_check·runner·store·file_processing 등) | **그대로** (manager 본체) |

## 4. 패키지/디렉터리 구조 (채택: B — public / _internal 분리)

```
packages/llm-request/
├── llm_request/
│   ├── __init__.py        ← public API (llm_request_async 등, 시그니처 불변)
│   ├── exceptions.py      ← 공개 예외만
│   ├── models.py          ← 공개 타입만 (StoredFile/FileInput/RequestMeta/Expire*)
│   ├── aio.py             ← llm_handler.aio re-export
│   └── _internal/         ← 구 service/app/logic 전부
│       ├── runner.py  keying.py  done_check.py
│       ├── store.py   meta.py    gemini_errors.py
│       ├── context_cache_lifecycle.py
│       ├── stored_file_resolver.py
│       ├── _config.py     ← 하드코딩 handler URL + 핸들러 초기화
│       └── file_processing/
│           ├── resolver.py cache_store.py dedup.py
│           └── uploader.py splitter.py validators.py
├── tests/
├── docs/  quickstarts/
└── pyproject.toml
```

> **`_internal/`의 의미 — 은닉이 아니라 계약 경계.** SDK는 설치 시 내부 코드가 전부 딸려가므로 사용자는 파일을 볼 수 있다(파이썬엔 강제 접근제어 없음). `_internal/`은 "public API 아님 · import 금지 · 예고 없이 변경"이라는 **신호 + 리팩토링 자유** 확보용이다. 진짜 코드 은닉은 서버(handler)만 가능하며, manager(SDK)는 본질적으로 코드를 숨길 수 없다.

## 5. 공개 API 표면 (예외 포함) — 정책: "노출은 하되 표면을 큐레이션"

§4의 `_internal` 철학과 동일하다 — SDK는 내부가 다 딸려가므로 **숨기려 들지 않고 공개 표면만 관용적 메커니즘으로 큐레이션**한다. 별도 wrapping/변환층을 만들지 않는다.

세 가지 메커니즘:
1. `__init__.py`에서 **공개할 이름만 import(re-export)** 해 노출.
2. `__all__`로 `from llm_request import *` 범위 제한.
3. 문서/타입 힌트에 **public API만** 기재.

### 예외 처리 적용

- `_internal`의 기존 예외 계층(`LLMRequestError` 베이스 + `CacheError`·`FileUploadError`·`ValidationError`·`FileResolveError`·`CacheKeyNotFoundError` + file size/type)은 **그대로 내부에서 raise.** 변환·재포장 없음.
- `__init__.py` + `__all__` + 문서에 **사용자가 잡을 의미 있는 것만** 올린다 (베이스 + 위 서브클래스).
- **HTTP 산물 제거**: `ServiceError`·`ServiceConnectionError`는 HTTP relay 전용이라 공개 표면에서 내린다. handler 도달 불가는 llm_handler의 `HandlerConnectionError`(이미 re-export)가 담당.
- llm_handler 예외(`HandlerError`·`HandlerConnectionError`)는 relay 계약대로 그대로 통과 (현재도 re-export 중).
- (완료) 베이스명 `LLMRequestServiceError` → `LLMRequestError` 로 개명 (서버 제거 후 'Service' 군더더기 정리).

> 함수·모델도 동일 원칙으로 `__init__` + `__all__` 큐레이션 (현 `__init__.py`가 이미 그 패턴).

## 6. 의식 사항 (단 하나)

`keying.py`가 **서버 1벌 → 여러 agent의 SDK N벌로 흩어진다.** 즉 키 생성 로직이 agent마다 각자 설치한 버전으로 실행되므로, "같은 입력 → 같은 키"가 서버 모드의 자동 보장에서 **버전 간 직접 지켜야 할 약속**으로 바뀐다.

- 서버 모드: keying.py 1벌만 실행 → 키 항상 일치 (서버 제거가 이 보장을 없앤다).
- SDK 모드: agent들이 제각각 다른 시점에 업그레이드 → canonicalize를 바꾸면 v1.2/v1.3 혼재 창에서 같은 입력이 다른 키를 내어 **캐시가 쪼개짐**(HIT 날 게 MISS → LLM 중복 과금).

→ 대응: **canonicalize 동결.** 안 건드리면 모든 버전이 같은 키라 분산돼도 안전. (file-manager도 키를 agent SDK에서 계산하는 같은 처지 — 동일 규칙으로 운영 중.)

> **이번 전환 자체는 스큐 없음.** 전 소비자를 한 번에 같은 SDK 버전으로 컷오버하므로 v1.2/v1.3 혼재 창이 없다. 위 동결 규칙은 **향후** 소비자들이 서로 다른 시점에 업그레이드하게 될 때를 위한 일반 원칙이다.

## 7. 전체 흐름 (서버 제거 후)

로직 자체는 현재와 **동일**하다. httpx 왕복과 FastAPI 계층만 사라지고, `__init__`이 `_internal` 함수를 직접 호출한다.

```
llm_request_async(llm_input, stored_files=..., cache_mode/save_mode/timings...)
  └─ _internal.runner.llm_request_async                     (← 기존 logic 그대로)
       ├─ _prepare_files(stored_files)        # resolve_stored_files: placeholder + mime/size 검증(fail-fast)
       ├─ prepare(...)                         # done_check → 키 생성 → MDB 조회 (hit/miss)
       │     └─ [hit] return (LLMResponse, meta)
       ├─ [miss] dedup.try_acquire_standby("agent_llm", key)
       │     ├─ leader → _do_llm_call → _build_server_call_input(resolve_files) → aio_call → finalize(MDB 저장)
       │     └─ waiter → wait_for_standby_release(주기적 MDB recheck) → hit면 재사용
       └─ return (LLMResponse, RequestMeta)
```

- 현재 `__init__`은 서버 JSON을 `LLMResponse(**result["result"])`로 되살렸지만, direct 모드에선 runner가 이미 `(LLMResponse, dict)`를 반환 → meta dict만 `RequestMeta`로 감싸 타입 반환 유지.
- handler 호출(mdb·redis·llm·file)은 그대로 각 handler **서버로 HTTP** (그건 handler니까 정상). 바뀐 건 "llm-request 자체가 서버가 아니게" 된 것뿐.

## 8. 모듈별 처리

| 모듈 | 처리 |
|---|---|
| `sdk/_client.py` (httpx AsyncClient) | **삭제** |
| `sdk/__init__.py` | `_get_client`/`AsyncClient` 제거 → `_internal.runner` 직접 호출. `close()`는 핸들러 정리(있으면)/no-op로 의미 변경 |
| `service/app/main.py`·`routers/` | **삭제** |
| `service/app/config.py` + `core/providers.py` | → `_internal/_config.py`: **하드코딩 handler URL 상수 + lazy 초기화**(`_ensure_configured()`, 첫 호출 시 llm_handler/file_manager/redis_handler configure — `_get_client` double-checked 패턴 재사용). port/host 제거 |
| `service/app/core/errors.py` | → `llm_request/exceptions.py`(공개). `_internal`이 여기서 import해 raise. `ServiceError`/`ServiceConnectionError`(HTTP 산물) 삭제 |
| `service/app/models/requests.py` | HTTP body DTO(`LLMRequestBody`/`DoneCheckBody`/`FetchBody`/`ExpireContextCacheRequest`) **삭제**. `StoredFile`/`FileKeyingMeta`는 공개 `models.py`로 통합(현 sdk/service 중복 제거). `FileInput`(bytes·file_path·resolved_via 포함)은 **내부 전용 → `_internal`로** (Phase 3 사용자는 StoredFile만 사용) |
| `service/app/models/responses.py` | **전체 삭제** (직렬화 불필요, runner가 객체 직접 반환) |
| `service/app/logic/*` | → `llm_request/_internal/*` 이동. **import 경로만** 변경 (`app.logic.x` → `llm_request._internal.x`) |
| 테스트 | `service/tests/logic/*` → `tests/_internal/*` (import 경로). router/HTTP/client-serialization 테스트 삭제 |

### config / 핸들러 초기화 (lazy auto-init)

handler URL이 하드코딩이므로 사용자가 호출할 init은 없다. 첫 public 호출 시 `_ensure_configured()`가 핸들러 SDK들을 하드코딩 URL로 configure (Gemini key 등 사용자 몫은 llm_handler 자체 설정 그대로). 현 `__init__._get_client`의 double-checked lock 패턴을 재사용.

## 9. 로드맵 — 클린 컷오버 (fallback 없음)

전 소비자를 한 번에 SDK로 전환하므로 이중 경로·버전 핀·서버 유지가 불필요하다. 서버 코드는 이번 작업에서 함께 제거한다.

1. **패키지 재배치 (구조 B)** — `service/app/logic/` → `llm_request/_internal/`. `sdk/_client.py`, `service/app/main.py`, `service/app/routers/`, `service/app/models/responses.py` 삭제. import 경로 일괄 치환(`app.logic.x` → `llm_request._internal.x`).
2. **config / 초기화** — `_internal/_config.py`: 하드코딩 handler URL 상수 + `_ensure_configured()`(lazy, double-checked). `config.py`의 port/host 제거.
3. **exceptions / models 정리** — 공개 `exceptions.py`(베이스+서브클래스, `ServiceError`·`ServiceConnectionError` 삭제), 공개 `models.py`(StoredFile/FileKeyingMeta/RequestMeta/Expire*로 통합·중복 제거). `FileInput`는 `_internal`로 내부화.
4. **`__init__` 재배선** — `_get_client`/`AsyncClient` 제거 → `_internal.runner` 직접 호출. `__all__` + 문서로 공개 표면 큐레이션(§5).
5. **테스트 이전** — `service/tests/logic/*` → `tests/_internal/*`(import 경로). router/HTTP/client-serialization 테스트 삭제. `pytest` 그린 확인.
6. **문서 동기화** — README / docs / quickstarts 갱신 (CLAUDE.md "문서 동기화" 규칙). 외부 API 시그니처 불변이므로 사용 예시의 import는 그대로, 내부 설명만 정정.
7. **소비자 일괄 전환 + 서버 내림** — rm/etf/esg 등 소비자 코드를 새 SDK 호출로 수정, llm-request 서버 인스턴스 종료.

> public API 시그니처 불변(§2)이라 7의 소비자 수정은 대부분 import/패키지 출처 변경 수준.
